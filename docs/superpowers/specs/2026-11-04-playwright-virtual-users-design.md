# Playwright 가상 사용자 설계

## 의도

CulturePick의 실제 브라우저 UI를 이용하는 로그인 기반 가상 사용자를 구현한다. 사용자는 페르소나에 따라 취향을 선택하고 추천을 탐색하며, 웹사이트에서 생성된 회원·찜·리뷰·행동 데이터가 실제 애플리케이션 경로로 저장되게 한다.

## 목표와 제외 범위

- Python Playwright Async API와 Headed Chromium으로 사이트를 이용한다.
- 사용자마다 별도의 `페르소나.md`를 읽어 이름, 관심 카테고리·태그, 검색 성향, 활동 성향을 얻는다.
- 상품 유형, 페르소나 파일 목록, 행동 선택 가중치, 대기 시간, 사용자 수, 행동 횟수, 사이트 주소를 하나의 JSON 설정에 둔다.
- 회원가입 후 취향을 저장하고, 그 취향으로 추천을 본 뒤 검색·목록·상세·스크롤·찜·찜 확인·리뷰·이전 페이지 이동을 수행한다.
- `random.choices()`로 매 단계의 행동을 확률적으로 선택하며, 실행마다 무작위 시드와 상태 기반 가드로 행동 흐름이 달라지게 한다. 행동 사이 대기는 설정된 범위의 `random.uniform()`으로 정한다.
- 누락된 UI 요소나 행동 오류를 해당 행동 기록에 남기고 다음 행동으로 진행한다.
- 사용자별 관심 카테고리·검색어 및 많이 조회한 태그를 계산하고, 실행 요약과 행동 이력을 JSON 파일로 기록한다.
- 실제 결제 또는 예약을 생성하지 않는다. 기본 대상은 로컬 CulturePick 사이트이며, 테스트 목적의 별도 설정에서만 대상 주소를 바꾼다.

## 접근 방식

1. 브라우저 DOM에서 화면을 확인하며 사용자 여정을 수행한다. 로그인·취향·추천 UI와 사용자 동작에 가까운 end-to-end 검증에 가장 적합하므로 권장한다.
2. API를 직접 호출해 계정과 활동을 생성한다. 빠르지만 UI에 실제 존재하는 선택지, 버튼, 페이지 이동을 확인하지 못한다.
3. UI 가입과 탐색은 브라우저로, 활동은 API로 혼합한다. 일부 API 상태를 만들기 쉽지만 한 사용자의 경로가 실제 사이트 경험을 대표하지 않게 된다.

선택: 1번. 사용자는 브라우저의 회원가입과 화면 동작을 통해 상태를 만든다. 파이썬은 실행 구성 및 JSON 결과 파일에만 직접 접근한다.

## 구성 요소

- `scripts/virtual_users/config.json`: 대상 사이트, 사용자 수, 사용자당 행동 수, 지연 구간, 상품 유형, 페르소나 파일 경로, 행동 가중치를 보유한다. 가중치는 행동 이름과 함께 읽기 쉬운 확률 숫자로 두고 실행 전 합계·값·행동 이름을 검증한다.
- `scripts/virtual_users/personas/*.md`: 실제 행동 성향을 담은 사용자별 페르소나 문서. 한 파일에는 한 페르소나를 두며, 설정에 명시된 파일만 로드한다. 선호 카테고리·태그·검색어·탐색 성향은 `##` 섹션과 줄 단위 목록으로 읽고, 목록이 없으면 안전한 기본값을 쓴다.
- `scripts/virtual_users/run.py`: CLI와 Async Playwright 수명, 설정과 페르소나 로드, 행동 선택·가드·기록, 결과 요약·직렬화를 담당한다.
- `scripts/virtual_users/results/`: 타임스탬프 기반 실행 JSON을 저장한다. 이메일·비밀번호는 기록하지 않고 가상 사용자 ID, 고른 취향, 성공/실패 행동, 콘텐츠 ID·태그만 남긴다.
- `requirements.txt`: 기존 Python 의존성과 충돌 없이 Playwright Python 패키지를 추가한다. Playwright Chromium 설치 방법은 스크립트 도움말 또는 프로젝트 테스트 문서에 안내한다.

## 사용자 흐름

각 사용자는 실행별 고유 이메일과 설정된 상품 유형을 기반으로 이름을 만든다. 브라우저에서 회원가입하고 같은 브라우저 컨텍스트의 세션을 유지한다. 가입 직후 표시되는 취향 설문에서 페르소나가 선호하는 카테고리와 태그를 골라 저장한다. 이미 등록된 동일 실행 사용자로 로그인하는 fallback은 설정으로 허용하되 기본 동작은 고유 계정 가입이다. 이후 메인, 카테고리, 검색, 목록, 상세, 스크롤, 추천, 찜 추가·확인, 리뷰 저장, 브라우저 뒤로 가기를 확률에 따라 시도한다. 사이트 이용 종료는 언제든지 선택될 수 있다.

## UI 상호작용과 실패 처리

- 테스트 식별자(`data-testid`)가 있으면 우선 사용하고, 그다음 role·accessible name·label을 사용한다. 결과적으로 찾은 요소가 없거나 숨김·비활성 상태면 클릭 또는 입력을 강행하지 않고 `skipped`와 이유를 기록한다.
- 라우트가 목록에 없거나 검색어가 결과를 만들지 않으면 임의 콘텐츠 ID를 만들지 않는다. API 응답/현재 DOM에서 발견한 상세 링크만 사용한다.
- 로그인 강제 UI가 뜨면 로그인 버튼으로 인증을 마친 뒤 현재 행동을 한 번 재시도한다. 인증이 불가능하면 행동을 실패 기록하고 실행을 지속한다.
- 각 행동을 예외 경계로 감싸되 브라우저 시작 실패, 잘못된 설정, 출력 저장 실패는 실행 수준 오류로 드러낸다.
- 리뷰 내용은 페르소나 기반의 짧은 생성 문장으로 만들고 웹 양식 유효 길이를 충족한다. 한 계정·콘텐츠 쌍의 리뷰를 덮어쓸 수 있는 API 동작을 고려한다.

## 실행 결과 계약

실행 JSON은 `run_id`, `started_at`, `finished_at`, `base_url`, `users`를 포함한다. 사용자 항목은 페르소나 ID·이메일을 제외한 사용자 식별 정보, 상품 유형, `selected_categories`, `selected_tags`, `search_terms`, `frequently_viewed_tags`, `actions`를 가진다. 각 행동 항목은 `timestamp`, `action`, `status`(`success`, `skipped`, `failed`), 안전한 요약 및 필요한 콘텐츠 ID를 기록한다. 비밀번호, 세션 토큰, 응답 헤더는 기록하지 않는다.

## 검증

- 구성·페르소나 파서: 잘못된 확률/경로, 빈 카테고리, 읽을 수 없는 파일의 오류와 기본값을 검증한다.
- 행동 러너: 무작위 행동 순서, uniform 지연 주입, 선택 요소 부재의 skip 및 예외 후 진행을 Playwright fixture와 spy로 검증한다.
- JSON 출력: 실행별 파일이 실제 스키마를 만족하며 비밀값을 포함하지 않는지 검증한다.
- 실제 headed Chromium으로 기본 로컬 사이트에 접속하여 테스트용 사용자를 생성하고 취향·추천·찜·리뷰 한 사이클을 검증한다. 이 작업은 서비스 애플리케이션의 test DB 사용을 전제로 하며 실제 결제는 수행하지 않는다.

## 구현자 판단

- 사용자 수와 각 사용자 행동 횟수는 CLI에서 설정 파일 기본값을 재정의할 수 있게 한다.
- 동시에 여러 headed Chromium 인스턴스를 여는 복잡성을 피하고, 사용자 하나를 끝낸 뒤 다음 사용자를 시작한다.
- 관찰 빈도는 상세 조회마다 본문 태그를 집계해 결정한다. 이벤트 DB 원본을 직접 조회하지 않는다.
