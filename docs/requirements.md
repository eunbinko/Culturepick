# 구현 요구사항

| 영역 | 구현 | 제한 |
|---|---|---|
| 회원 | 가입, 로그인, 서버 세션, 로그아웃, 이름 수정 | 이메일 인증/비밀번호 재설정은 후속 범위 |
| 취향 | 관심 분야·태그 저장/수정 | 알고리즘 학습 없이 가중치 기반 |
| 탐색 | 검색, 지역·분야·기간·무료, 정렬, 페이징, 상세 | 외부 API 키 설정 전 가상 샘플 제공 |
| 활동 | 찜, 리뷰·평점, 최근 조회, 추천 노출/클릭 | 로그인한 본인 활동만 수집 |
| 추천 | 설문+시간감쇠 조회+현재 찜, 추천 이유 | 재방문 조회 1일 중복 점수 제한, 최대 500개 후보 |
| 결제 | PortOne V2 SDK, 서버 검증, 서명 웹훅, 이력, 검증 후 예약 | 실제 PG/판매 콘텐츠·팀 정책 설정 필요 |
| 환불 | 비활성 기본값, 설정 시 행사 시작일 전 전액 취소 | 부분 환불·수수료·사용 확인은 정책 미확정 |
| 수집 | 문화포털 목록·상세, 정규화, 중복 갱신, 주기 실행 | 키/할당량 및 이용 조건 확인 필요 |
| 배포 | Nginx 정적, FastAPI 직접 호출, MariaDB 독립 서버 | 운영 도메인/TLS·방화벽은 운영자가 구성 |

MariaDB만 사용하며 SQLite·MongoDB를 도입하지 않는다. 잔여 좌석/잔여 매수 표시와 무료 크레딧 결제는 제공하지 않는다. 샘플 정보로 실제 결제를 생성할 수 없다.
